# 2026-07-23 — Combined SFT, GRPO results, the OOD reframe, and RAG

Covers everything since [2026-07-21](2026-07-21.md): the combined-data SFT result,
GRPO full runs + eval, the knowledge-injection experiments, a critical correction
to how we read "OOD", the RAG anatomy-retrieval pipeline, and the finding that the
OOD ceiling is LLM-side (not the vision encoder).

---

## 1. Combined-data SFT — situs recovered (the data-diversity win)

Trained `combined-9b-8r-direct` (LoRA r8, direct prompt) on heico + lapchole train.
Evaluated on both.

| lapchole (OOD) | heico-only SFT | **combined SFT** | Δ |
|---|---|---|---|
| overall | 0.439 | **0.558** | +11.9 |
| **situs** | 0.071 | **0.821** | **+75** |
| fo_class | 0.421 | 0.643 | +22 |
| open_ended | 0.503 | 0.669 | +16.6 |

situs CIs are non-overlapping ([0,0.21] vs [0.64,0.98]) — a real recovery, not
n=25 noise. heico (in-dist) also improved slightly (0.613→0.621). **Catastrophic
forgetting of cross-procedure anatomy is fully reversed by procedure-diverse
training.** All checkpoints kept (`save_total_limit=15`) for GRPO seeding.

## 2. GRPO — full warm + cold runs, evaluated

Both trained on combined data, 400 steps, direct prompt, KL β=0.04, G=10, bs=40.

- **Warm** (init from heico-only r8 SFT): reward plateaued at +0.04 by step 100;
  `frac_reward_zero_std` climbed 0.36→0.45 (advantage collapse). Eval (ckpt-400):
  lapchole overall 0.445, **situs 0.071**, fo_class 0.447. So GRPO healed OOD
  modestly (fo_class/binary/object-id +2–3pt, monotonic) but **situs stayed 0**.
- **Cold** (from base): lower reward but still climbing; huge KL drift (→0.39).
  Eval: overall 0.333, **situs 0.488** (kept base's anatomy — never did SFT
  forgetting), but weak format.

**Key finding: knowledge is learned by SFT, not RL.** GRPO trained on lapchole data
yet situs stayed 0.07 — RL amplifies what's sampled, it doesn't install knowledge.

### Bug: warm-GRPO eval needs base+SFT merged
The warm GRPO adapter was trained on `base + merged SFT`, so evaluating it as
`raw base + GRPO adapter` gives garbage (fo_class 0.12). Fix: built
`orena_grpo/base_plus_sft_8r` (merge script `orena_grpo/merge_sft.py`) and pass it
as `--base-model-id`. Cold-start uses raw base (no merge).

## 3. Knowledge-injection experiments (heico-only SFT, lapchole — TRUE OOD)

Added `--condition-procedure`, `--inject-knowledge {anatomy,fo_priors,both,rag}`,
`--fo-definitions` to `evaluate_qwen_frame.py` (and base). All inference-time,
additive, keyed on `procedure_type` (given at inference).

| lever | situs | fo_class | overall |
|---|---|---|---|
| unconditioned | 0.071 | 0.421 | 0.439 |
| procedure conditioning (name only) | 0.429 | 0.421 | 0.434 |
| **static curated anatomy** | **0.571** | 0.417 | 0.430 |
| RAG anatomy | 0.393 | 0.430 | 0.436 |
| **fo_priors** (procedure-typical FO) | 0.262 | **0.489** | 0.468 |
| fo_definitions (full official defs) | 0.071 | **0.494** | 0.455 |
| anatomy+FO (both) | 0.524 | 0.468 | 0.444 |

Findings:
- **Procedure conditioning recovers situs** (0.07→0.43) — SFT *suppressed* the
  knowledge, didn't destroy it; the procedure signal surfaces it. On base:
  0.46→0.74.
- **fo_priors is the best overall lever** (fo_class +6.8pt on 41% of questions).
- **fo_definitions**: hurts in-distribution (−3pt, distracting 700 tokens) but
  helps OOD fo_class (+7pt) — an OOD recognition crutch; help scales with how
  unfamiliar the procedure is (heico-only lapchole +7.3 ≫ combined lapchole +1.2).
- **Injecting anatomy + FO together interferes** — each block is noise for the
  other's questions. → gate injection by question type.
- **Metric caveat:** situs is 25/2252 = 1.1% of questions, so its swings barely
  move micro `overall MEAN`. Macro-over-capabilities shows the situs win (+5.6);
  micro hides it. **Must confirm the challenge's official aggregation.**

## 4. ⚠️ The OOD reframe (the most important correction)

**Combined SFT trained on lapchole → its lapchole test is in-distribution, NOT
OOD.** Ranking it #1 "on OOD" was wrong. The only genuine OOD numbers are the
**heico-only → lapchole** runs (model never trained on cholecystectomy).

- **True far-OOD ceiling ≈ 0.47** (heico-only + best lever).
- **Combined SFT's 0.56 is the in-distribution ceiling** — only reachable for a
  procedure whose data you have.
- **GRPO's lapchole is only *nominally* in-distribution** (saw data via RL, didn't
  learn it → situs 0.07).

Real generalization gap: heico-only 0.61 ID → 0.44 far-OOD = **−0.17**. Combined's
−0.06 is two in-distribution scores, not a gap.

**Solution for a novel test procedure** (the actual challenge): (1) maximum
procedure diversity in SFT — shrinks distance to novel procedures + builds
procedure-conditioning invariance; (2) inference-time levers (conditioning / RAG /
FO-priors) — the only things that help a genuinely unseen procedure, need no
training on it; (3) leave-one-procedure-out validation. Realistic target
**~0.47–0.48, not 0.56**. Full ranked table: `evaluation_summary.md`.

## 5. RAG anatomy retrieval — built and validated

Motivation: for a **novel** procedure we can't add training data, but we get
`procedure_type` at inference. Retrieve that procedure's anatomy from a bundled
offline corpus and inject it → the model *reads* anatomy instead of *recalling* it.
Full description: `orena_rag/rag.md`.

- **Corpus**: Wikipedia surgery/anatomy, harvested by **category** (seed-driven root
  discovery, not keyword) → semantic-filtered to drop drift → **1,282 articles →
  2,013 passages**, MiniLM 384-dim embeddings. Built by `orena_rag/build_rag_index.ipynb`,
  cached in `orena_rag/rag_index/`.
- **Retriever** (`orena_rag/retriever.py`): query = `procedure_type + " surgical
  anatomy"` → cosine over passages → **abstain if top score < 0.58** (never inject
  wrong anatomy) → morphological fallback (`cholecyst-ectomy → cholecyst`) → top-4
  passages, cached per procedure.
- **Validated 9/9** coverage + correctness, 3/3 abstain on nonsense (Sigmoid→sigmoid
  colon, Whipple→pancreas/duodenum, negatives→abstain).
- **Wired into eval**: `--inject-knowledge rag --rag-index <dir>`; predictions now
  log `retrieve_time` + `full_time`.
- **Latency negligible**: retrieve_time **0.3 ms**, full_time **214 ms** amortized
  (cached per procedure) — trivial vs the 5 s budget.

**Result: RAG situs 0.07→0.393** — real recovery, but *below* the hand-tuned static
block (0.571). Why: the query retrieves the **procedure article** (Cholecystectomy —
describes the *operation*), not the **anatomy-location** text. Next lever: bias
retrieval toward anatomy articles / full text, or a biomedical embedder.

## 6. The OOD ceiling is LLM-side, not the vision encoder

Hypothesis (worth testing): maybe ~0.47 is a perception/encoder limit. **Refuted by
existing data:** SFT LoRA targets are language-only (`q/k/v/o_proj`, MLP) — the
**vision encoder was frozen** in every run. heico-only (frozen enc) → 0.44;
combined (SAME frozen enc, +lapchole LLM training) → 0.56. Same encoder, only LLM
differs → the encoder's lapchole features suffice for 0.56 → **the ceiling is LLM
adaptation, not the encoder.** DINOv3 is therefore *not* the lever for OOD. The one
place perception plausibly limits: **`number`** (fails even in-distribution ~0.48).

## 7. Data note: SFT eval split ≠ dataset's official val

`sft_export/heico/eval.jsonl` uses videos {0008 Prokto-9, 0010 Rektum-1},
self-generated by `make_eval_video_split` (seed 42, from FOCUS TRAIN records). The
dataset's built-in val (`val.lance` = `internal_val_videos.json`) is a *different*
set {0000, 0001, 0013, 0014}. Same seed, different source list → different draw. Not
a leak (held out of our train), but not the authors' official val either.
